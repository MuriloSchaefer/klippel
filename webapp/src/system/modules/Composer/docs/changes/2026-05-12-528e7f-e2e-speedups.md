## Context

The e2e suite under `webapp/src/**/mcpTools/tests/*.e2e.test.ts` drives a real Electron instance over CDP through puppeteer. Today's setup is conservative — fine when nothing breaks, slow when iterating:

- [jest.config.ts](webapp/jest.config.ts) pins `maxWorkers: 1`. Every test file runs serially against a single Electron on `:9222`.
- [resetWorkspace.ts:32-42](webapp/src/helpers/puppeteer/resetWorkspace.ts#L32-L42) wipes `.session/`, rewrites `Store/state.json`, then does a full `page.reload({ waitUntil: 'domcontentloaded' })` per test file. Reload re-boots the entire renderer (Redux + workspace load + module init) — the single biggest per-file cost.
- Per-file `beforeAll` typically does: reset → switch ribbon tab → `createModel` → `openModel` → `openGarmentDetails`. That's ~5 sequential UI round-trips before the first assertion.
- [linkProcessElective.e2e.test.ts:39-50](webapp/src/system/modules/Composer/mcpTools/tests/linkProcessElective.e2e.test.ts#L39-L50)-style `closeAllOpenContainers` runs in `beforeEach`, polling up to 5× with a hard `{ timeout: 500 }` even when no panel is open.
- Test-level timeouts are generous (60s setup, 90s/test) which hides slowness rather than enforcing budgets.
- [jest.globalSetup.ts:11](webapp/jest.globalSetup.ts#L11) gives the cold Electron boot up to 90s; warm reuse is already supported via `probeCdp()` early return but is undocumented for local dev.
- ts-jest runs every `.ts` through the TypeScript compiler. On a multi-thousand-line module graph this dominates worker startup.

## Goals

1. Cut single-file wall time roughly in half (skip the per-file Electron reload when possible).
2. Allow opt-in parallelism across files via multiple Electron instances on distinct CDP ports.
3. Tighten loops/timeouts that gate fast-path behavior (`closeAllOpenContainers`, escape polling).
4. Replace ts-jest with a faster TS transform (swc) for worker spin-up.
5. Document the warm-Electron workflow for local iteration.

Non-goals: rewriting the test surface, changing assertions, or coverage thresholds.

## Change

### 1. Soft workspace reset (no full page reload)

Replace the `page.reload()` step in `resetWorkspace` with an in-app workspace switch + Redux rehydrate, falling back to reload only when the renderer reports a mismatched workspace.

- Add a kernel call `Workspace/reload` (or reuse the existing "select workspace" path) that re-reads `Store/state.json` and re-mounts the workspace subtree without tearing down the renderer.
- Driver responsibility: dispatch the kernel call, then `waitForSelector('#ribbon-menu-tabs')` (cheap — element is already mounted).
- Keep `page.reload()` as a `--hard` opt-in via env (`KLIPPEL_E2E_HARD_RESET=1`) for the CI matrix that distrusts shared state.

**Expected win:** ~2–4s per test file (renderer boot is the heaviest cost in `beforeAll`).

### 2. Shared "ready" workspace fixture

Most Composer tests redo the same scaffolding: create a model, open it, open garment details. Promote that to a base workspace shipped under `~/klippel/envs/small-app/workspaces/composer-ready` (or generated lazily on first run by a single setup test), and have tests pass `BASE_WORKSPACE=composer-ready` so the `beforeAll` only resets + (soft) reloads.

- Generate the fixture in a dedicated `_fixtures.e2e.test.ts` that runs first when fixtures are stale (checksum the source-of-truth schema files).
- Fixture is FS-only; no per-file dependency on `createModelTool` + `openModelTool` + `openGarmentDetails`.

**Expected win:** ~1.5–3s per test file (skip 3 sequential UI tool calls).

### 3. Parallel CDP instances

Allow `maxWorkers: N` by launching one Electron per worker with isolated state:

- [jest.globalSetup.ts](webapp/jest.globalSetup.ts) reads `JEST_WORKER_ID` (Jest sets it per worker) and computes `CDP_PORT = base + worker`, `ENV_NAME = ${base}-w${worker}`, `--user-data-dir=...-w${worker}`.
- Resolve `KLIPPEL_CDP_PORT` in the same way at the test layer so puppeteer connects to the right port.
- Teardown kills the per-worker process group (already implemented; just keyed by worker id).
- Gate behind `KLIPPEL_E2E_WORKERS` env (default 1) so CI can opt in and local dev keeps the simple single-instance model.

Risks: each Electron consumes ~300MB and a GPU process; on the CI box with 2 cores 2 workers is the realistic ceiling. Document the cap.

**Expected win:** 1.5–2× on multi-file runs; linear in worker count.

### 4. Tighten the close-containers loop

In [linkProcessElective.e2e.test.ts:39-50](webapp/src/system/modules/Composer/mcpTools/tests/linkProcessElective.e2e.test.ts#L39-L50) and twins, `closeAllOpenContainers` always waits up to 500ms per iteration. Replace with:

- Single `await page.$('[role="pointer-panel-content"], ul[role="listbox"]')` — return immediately if null (clean state, the common case).
- Drop the explicit `waitForSelector({ hidden: true, timeout: 500 })`; rely on the next assertion's wait, or use `{ timeout: 100 }` to bound it tighter.
- Extract to `webapp/src/helpers/puppeteer/closeOverlays.ts` (per `mcp-puppeteer-tools` skill: shared helpers live under `helpers/puppeteer/`). Drivers and tests both reuse it.

**Expected win:** ~250–400ms × test count = a few seconds per file. Cumulative across the suite.

### 5. Tighter, explicit per-step timeouts

The current 90s/test ceiling means a stuck `waitForSelector` burns 90s before failing. Lower per-test budgets:

- `*.e2e.test.ts` per-`it` timeout: 30s (was 90s).
- `waitForSelector` defaults dropped to 5s for "should already exist" elements and kept at 10s for "must appear after an action".
- `beforeAll` timeout: 30s once fixtures land (was 60s).

This doesn't make passing tests faster but makes failing tests fail an order of magnitude faster, which is most of the developer-time win when iterating.

### 6. swc transform instead of ts-jest

Swap [jest.config.ts:17-24](webapp/jest.config.ts#L17-L24) to `@swc/jest`. swc is ~5–10× faster on cold TS compile and keeps the existing module-name mapper / ESM treatment.

- Required: `@swc/jest` + a `.swcrc` (or inline config) that mirrors `tsconfig.json` paths.
- Watch out: ts-jest's `useESM: true` + `extensionsToTreatAsEsm` need to be reconciled with swc's ESM output. Validate by running the suite once with both transforms and diffing outcomes.
- Keep type-checking out-of-band (`tsc --noEmit` in CI), since swc skips it — the e2e suite catches behavior regressions, not type drift.

**Expected win:** 2–6s off cold worker startup (matters more once parallel workers are in play).

### 7. Document warm-Electron iteration

The existing `probeCdp()` early-return already supports "leave `npm run dev` running and run tests against it". Today this is undocumented:

- Add a short section to the Composer test README (or create one) describing the workflow: terminal A `npm run dev`, terminal B `ENV_NAME=small-app BASE_WORKSPACE=empty npx jest path/to/foo.e2e.test.ts`. The setup detects CDP and skips the 90s boot.
- Add a one-line console log in `globalSetup` when reusing a found instance (currently silent), so devs know it picked up the running app.

## Sequencing

These are independent and can land in separate PRs:

1. (4) close-overlays helper + (5) tighter per-test timeouts — pure mechanical, no infra changes. Land first to lock in the cheap wins.
2. (7) document warm-Electron workflow.
3. (1) soft workspace reset — needs a kernel call and broader testing across modules.
4. (2) shared `composer-ready` fixture — depends on (1) for the soft-reload path.
5. (6) swc transform — independent but riskier; needs a green-suite comparison run.
6. (3) parallel workers — biggest blast radius (multi-Electron infra). Land last so the rest of the wins are validated under serial execution first.

**Item 1 (soft workspace reset) — shipped opt-in:**

- Built on top of [2026-05-12-b26755](webapp/src/kernel/modules/Store/docs/changes/2026-05-12-b26755-session-inside-workspace.md). Per-workspace `.session/` was the prerequisite — once each slice's `storage` routes by current workspace, switching workspace is enough to redirect future writes; rehydrate fills in past reads.
- `webapp/src/kernel/modules/Store/workspaceScope.ts` adds a rehydrator registry: `defineRehydration<T>(actionType, restorer)` returns a Redux action and registers an async restorer that re-reads `.session/<Module>` under the *current* workspace.
- `Store/middlewares.ts` `selectWorkspace` listener now runs `runAllRehydrators()` and dispatches each result before emitting `workspaceSelected`. Slices that registered a rehydration handle the action by replacing their state.
- 10 slices wired (cover the e2e-critical surface — viewports, models, variations, materials, materialTypes, panels, viewports/groups, graphsManager, SVG, Layout theme). Non-critical slices (`Loader`, `Markdown`, `Converter`, `Orders`, `Composer/store` top, `Materials/store` top, `Layout/ribbonMenu`) keep their captured-at-boot `initialState` after a soft switch — fine for tests that don't depend on them.
- `DynamicStore.tsx` exposes the configured store as `globalThis.__klippelStore__` (cheap, harmless outside tests).
- `webapp/src/helpers/puppeteer/resetWorkspace.ts` exports `softResetWorkspace(page, target, base)`: same FS prep as `resetWorkspace` but instead of `page.reload()` it `page.evaluate`s a `selectWorkspace` dispatch. Wait selector unchanged.
- `resetWorkspace` (hard reset) kept as the default for all e2e tests; tests can opt into `softResetWorkspace` per-file.

**Not yet validated against a real Electron boot.** Expected wins (~2–4s per test file) and remaining risks (React-tree state held in component-local `useState`, e.g. open accordions / focused row tracking) called out in the b26755 change doc.

**Still planned (items 2, 3):** `composer-ready` fixture, parallel CDP instances. See sequencing above.

Open questions before implementation:

- Soft reset (1): does the renderer survive a workspace switch without leaking module state from the prior workspace? If subscriptions in `Pointer` / `Composer` don't fully tear down, we keep the hard-reload path and only chase items 2–7.
- swc (6): does `useESM: true` + the `.js`-suffix moduleNameMapper for relative imports still resolve cleanly under swc's transform? If not, an `esbuild-jest` variant may be the safer swap.
- Parallel (3): need to confirm `~/klippel/envs/<env>` is the only on-disk state — any global lock files (e.g. on `.session`) would serialize workers regardless of separate user-data-dirs.

## Security

None. Test-infrastructure only; no change to production code paths, no new auth/input surface.

## Performance

This change *is* the performance work. Targeting a 2–3× reduction in suite wall time after (1)+(2)+(6) land, and another 1.5–2× from (3) on multi-core hosts. Compounded: a current ~Xs serial run could become ~X/4–X/6 on the CI box.
